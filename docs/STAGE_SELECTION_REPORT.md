# Stage-selection report

The selector is driven by `GOVERNED_STAGES`, not a second ad hoc stage list. It supports one, several, or the complete ten-stage run; previews selected order; warns about omitted dependencies and missing blind discovery; enforces discovery-first ordering when selected; and writes requested/executed stages plus an empty hidden-reruns list to provenance.

The stages currently create a governed candidate packet and receipt. Only the fixture provider mapping populates normalized proposal fields. Production provider-stage orchestration remains a gap and must not be represented as executed AI analysis.
